# SSH + SFTP 生产低影响只读诊断模式设计

## 文档状态

- 状态：设计方案，尚未实现
- 目标版本：待排期
- 适用范围：SSH 工具中的生产连接、SFTP 和远程诊断入口
- 核心决策：生产模式只允许低影响、被动、有界的只读诊断，不提供完整交互 Shell
- 配套文档：[生产诊断实现与验证计划](ssh-sftp-implementation-plan.md)

本文记录 SSH 生产模式的产品语义、安全边界、用户行为、技术架构、资源限制、测试标准和分阶段落地方案。实现与本文不一致时，应先更新设计并明确原因，不能静默降低生产保护等级。

## 结论先行

生产模式定义为：

> **低影响只读诊断模式：允许排查问题，但禁止修改远端数据、改变系统状态，或执行可能明显影响生产性能和可用性的操作。**

目标行为如下：

1. SFTP 允许浏览、预览和下载，禁止上传、新建、编辑、重命名和删除。
2. 生产连接禁止启动完整 Bash、Zsh、PowerShell 等交互 Shell。
3. 终端区域改为结构化的“安全诊断终端”，只提供明确允许的只读操作。
4. 未知、无法证明安全、资源消耗不可控的操作一律拒绝。
5. 被拒绝的操作不得发送到 SSH 子进程或远端服务器。
6. 不提供单条命令的“仍然执行”或临时绕过入口。
7. 客户端保护主要防止通过 Ramag 误操作；需要不可绕过的限制时，必须增加服务器端权限和隔离。

## 背景与当前实现

当前 `SshProfile.production` 的语义是“保留 SSH Terminal，仅禁止 SFTP 远程写操作”。应用层和基础设施层已经对 SFTP 写操作进行双重校验，但生产连接仍会创建普通的 `ssh -tt` 交互终端。

现有终端链路为：

```text
键盘 / 输入法 / 粘贴
        ↓
TerminalView
        ↓ 原始字节
TerminalCore
        ↓ PTY
系统 OpenSSH：ssh -tt
        ↓
远端默认 Shell
```

客户端无法可靠知道原始字节最终产生的远端副作用。命令可能来自历史记录、别名、函数、脚本、解释器、编辑器 Shell escape、嵌套 SSH 或终端复用器。因此，完整终端上的危险命令黑名单只能减少部分误触，不能形成可信的“禁止修改”边界。

目标设计不在这条原始字节链路中增加业务黑名单，而是让生产连接不再进入该链路。

## 设计目标

### 功能目标

1. 支持日常生产问题排查：系统资源、进程、端口、文件、日志和服务状态。
2. 禁止通过 Ramag 修改远端业务数据、文件、配置和运行状态。
3. 限制诊断操作的并发、耗时、范围和输出，避免只读操作拖慢生产系统。
4. 生产保护在 UI、应用层和基础设施层均有明确门禁。
5. 所有允许和拒绝行为均可通过自动化测试验证。
6. 非生产连接继续使用现有完整交互终端，不改变其行为。

### 安全目标

1. 默认拒绝：只有明确建模并验证过的操作可以执行。
2. 最小能力：操作请求只表达诊断目的，不携带任意程序和 Shell 参数。
3. 失败关闭：配置读取、策略判断、平台识别或参数校验失败时拒绝执行。
4. 不自动重试：避免超时或连接故障触发重复诊断负载。
5. 无隐式降级：安全终端失败时不能自动回退到完整 Shell。

## 非目标与承诺边界

### 第一版非目标

1. 不支持任意 Shell 命令的安全解析和执行。
2. 不试图识别全部 Linux、macOS、Windows 或第三方工具的危险参数。
3. 不提供部署、重启、修复、回滚等生产变更能力。
4. 不把客户端模式描述为服务器级访问控制。
5. 不提供合规级审计存储；第一版只记录必要的应用诊断日志。
6. 不承诺远端操作系统完全零写入。

### 为什么不能承诺零影响

任何读取都会消耗少量 CPU、内存、磁盘或网络资源，还可能更新缓存、访问时间或审计日志。因此，本模式的准确承诺是：

> 不主动执行持久化修改，不改变服务、进程和系统状态，并通过资源预算把诊断影响限制在预设范围内。

### 威胁模型

客户端模式主要防护：

- 用户连接错生产主机。
- 复制、粘贴或输入了错误命令。
- 紧急排障时误删文件、重启服务或执行部署。
- 用户误以为 SFTP 只读也意味着普通终端只读。

客户端模式不单独防护：

- 用户改用系统终端或其他 SSH 客户端。
- 用户主动关闭生产模式。
- 远端账号本身拥有过高权限。
- 远端服务器、Shell 启动配置或系统工具已经被恶意篡改。

需要防护这些场景时，必须使用独立只读账号、服务器权限、强制命令、容器或其他隔离机制。

## 核心术语

### 远端数据

包括但不限于：

- 数据库、缓存、消息和业务文件。
- 配置、日志、密钥、证书和用户文件。
- 文件内容、名称、路径、权限、所有者和时间属性。
- 容器、镜像、软件包和部署产物。

### 系统状态

包括但不限于：

- 服务、进程、容器和任务的运行状态。
- CPU、内存、磁盘、网络和进程资源限制。
- 路由、防火墙、DNS、挂载点和内核参数。
- 用户、用户组、权限、认证和定时任务。
- 系统时间、主机名和软件安装状态。

### 低影响被动诊断

同时满足以下条件的操作：

1. 只读取已经存在的信息。
2. 不主动调用可能产生业务副作用的接口。
3. 不向目标进程发送信号或附加调试器。
4. 扫描范围、运行时间和输出大小都有硬上限。
5. 参数异常时不会退化为全盘扫描或无限等待。

## 操作分类与决策规则

每个安全诊断操作必须归入以下一类：

| 分类 | 定义 | 生产模式行为 |
|---|---|---|
| `PassiveRead` | 被动、有界、低影响读取 | 允许 |
| `ActiveProbe` | 主动向服务、网络或进程发送探测 | 默认拒绝 |
| `StateChange` | 修改数据或运行状态 | 禁止 |
| `Unbounded` | 范围、耗时或资源消耗不可控 | 禁止 |
| `Unknown` | 无法确认行为或平台不支持 | 禁止 |

允许执行前必须同时满足：

1. 操作类型为 `PassiveRead`。
2. 使用结构化参数，不接受自由 Shell 文本。
3. 所有参数通过长度、格式、范围和语义校验。
4. 存在超时、输出和并发限制。
5. 执行实现不包含用户可控的程序路径、环境变量或 Shell 片段。

任何一项不满足都必须在本地拒绝。

## 第一版允许的诊断能力

第一版只覆盖高频、可明确约束的 Linux 远端诊断。后续扩展必须逐项评审，不能提供用户自定义的任意白名单命令。

| 操作 | 用途 | 初始限制建议 |
|---|---|---|
| 系统概况 | 主机名、系统版本、时间、运行时间和负载快照 | 无用户参数；5 秒超时；256 KiB 输出 |
| 资源快照 | CPU、内存和交换区概况 | 单次快照；5 秒超时；512 KiB 输出 |
| 进程列表 | 查看 PID、用户、CPU、内存和命令摘要 | 最多 5,000 行或 2 MiB；筛选在本地完成 |
| 端口与连接 | 查看监听端口和连接快照 | 单次快照；最多 5,000 行或 2 MiB |
| 磁盘概况 | 查看文件系统整体容量和使用率 | 禁止递归目录统计；5 秒超时 |
| 文件元信息 | 查看类型、大小、权限、所有者、时间和校验值 | 每次一个路径；禁止设备、Socket 和 FIFO |
| 文件片段 | 查看普通文件的头部、尾部或指定窗口 | 每次最多 2 MiB；不支持编辑和持续跟随 |
| 日志查询 | 查看指定文件或服务在有限时间范围内的日志 | 最多 5,000 行或 2 MiB；不支持 `follow` |
| 服务状态 | 查看服务是否运行及基础状态 | 只允许状态类操作；禁用分页器；5 秒超时 |

补充规则：

- 下载把内容写入本地，不修改远端，因此可以保留；本地覆盖仍沿用现有覆盖确认策略。
- 文本搜索、排序和过滤优先在本地结果上完成，避免远端任意管道和重复 IO。
- `/proc`、`/sys` 等伪文件不能走通用文件读取，必须通过专用、已验证的诊断操作访问。
- 数据库诊断优先使用 Ramag 已有数据库工具及其生产只读保护，不通过 SSH 启动数据库 CLI。
- Docker、Kubernetes 和云平台操作第一版不开放；这些凭据和 API 往往同时具有读写能力，需要独立设计。

## 明确禁止的行为

### 数据和文件修改

- 新建、写入、追加、截断、移动、重命名或删除文件。
- 修改权限、所有者、ACL、扩展属性和时间属性。
- 上传文件、编辑文件和解压覆盖。
- 使用输出重定向、Here Document 或其他隐式写入方式。

### 系统和运行状态修改

- 启动、停止、重启、重载、启用或禁用服务。
- 终止进程、发送信号、调整优先级或资源限制。
- 安装、升级、卸载软件和修改软件源。
- 修改网络、路由、防火墙、DNS 和流量控制。
- 挂载、卸载或格式化文件系统和磁盘。
- 修改用户、用户组、密码、密钥、认证和定时任务。
- 修改内核参数、系统时间和主机名。
- 创建、删除、重启或进入容器和工作负载。
- 部署、回滚、构建、迁移和执行数据库写操作。

### 看似只读但影响不可控

以下操作即使不直接写数据，第一版也必须拒绝：

| 示例 | 拒绝原因 |
|---|---|
| `find / ...` | 可能扫描整个文件系统 |
| `du /` | 可能产生大量磁盘 IO |
| `grep -R /` | 范围和耗时不可控 |
| `strace`、`gdb`、`perf` | 可能暂停或明显拖慢目标进程 |
| `tcpdump` | 持续占用资源并读取敏感流量 |
| 任意 `ping`、`curl` | 属于主动请求，可能触发业务副作用 |
| `tail -f`、`journalctl -f` | 长时间占用连接和资源 |
| `top` | 交互模式可能发送信号或修改优先级 |
| `docker exec`、`kubectl exec` | 可绕过全部命令限制 |
| 任意数据库 CLI | 后续输入无法可靠限制为只读 |
| 大范围只读 SQL | 可能拖慢或阻塞数据库 |

### 任意执行和逃逸入口

- Bash、Zsh、Fish、PowerShell 等完整 Shell。
- Python、Node.js、Ruby、Perl 等通用解释器。
- 任意脚本、用户上传的可执行文件和自定义程序路径。
- `sudo`、`su`、`doas`、`pkexec` 等权限提升入口。
- 编辑器、分页器、调试器的 Shell escape。
- 管道、命令替换、后台任务、别名、函数和嵌套 SSH。

## 用户可见行为

### 打开生产连接

1. 工作区持续显示醒目的“生产 · 低影响只读诊断”标识。
2. SFTP 写入口禁用，读入口保持可用。
3. “终端”入口打开安全诊断终端，而不是完整 Shell。
4. 用户从操作列表选择诊断类型，并填写受控参数。
5. UI 在执行前显示目标主机、用户、操作类型和资源边界。
6. 参数校验或策略判断失败时就地说明原因，不创建 SSH 执行任务。
7. 生产模式不显示“仍然执行”“临时允许”或相同含义的按钮。

### 从非生产切换为生产

已有完整终端不能继续保留，否则新策略无法约束它们。切换流程如下：

1. 用户保存生产模式。
2. UI 立即冻结该配置下所有终端的新输入。
3. 如果存在活动终端，显示将关闭的终端数量和影响说明。
4. 用户确认后关闭全部本地 PTY 和 SSH 子进程，再保存生产状态。
5. 用户取消时恢复终端输入，配置保持非生产。
6. 保存完成后，工作区切换为安全诊断终端。

关闭本地 SSH 不能撤销已经执行的远端修改，也不能保证通过 `nohup`、后台任务等启动的远端进程立即结束。确认文案必须如实说明这一点。

### 从生产切换为非生产

这是降低保护等级的操作：

1. 明确展示目标主机和用户。
2. 要求输入连接名称确认。
3. 记录降级操作及时间。
4. 只允许新建完整终端，不恢复历史终端进程。

第一版不引入账号体系或管理员权限，因此该确认只能防止误触，不能阻止有意降级。

### 工作区恢复和配置变化

- 应用重启后只恢复生产工作区，不恢复任何终端进程。
- 启动执行前必须根据 `profile_id` 读取最新已保存配置，不能只相信工作区中的旧副本。
- 配置被删除或读取失败时拒绝启动完整终端和安全诊断操作。
- 检测到生产标记变化时，应先冻结相关终端输入，避免旧视图继续发送字节。

## 目标架构

```text
SshProfileId
     ↓
SshService 读取最新配置
     ↓
     ├─ production = false
     │      ↓
     │  terminal_command
     │      ↓
     │  TerminalView → TerminalCore → PTY → ssh -tt
     │
     └─ production = true
            ├─ terminal_command：Forbidden
            │
            └─ execute_diagnostic(operation)
                    ↓
               策略与参数校验
                    ↓
               资源预算
                    ↓
               SshDriver
                    ↓
               ssh -T / 服务端安全网关
```

核心原则：拒绝决定发生在创建远端执行任务之前。

## 技术实现说明

领域模型、crate 分层、输入校验和 Shell 构造规则见配套的[生产诊断实现与验证计划](ssh-sftp-implementation-plan.md)。该文档是本设计的实施部分，不能脱离本文的产品语义和安全边界单独解释。

## 资源预算

第一版建议使用以下初始预算，实测后可以收紧或按操作细分：

| 资源 | 初始限制 |
|---|---|
| 单配置并发诊断 | 1 个 |
| 全局并发诊断 | 4 个 |
| 默认超时 | 10 秒 |
| 单操作硬超时 | 30 秒 |
| 单次输出 | 2 MiB |
| 单次文本行数 | 5,000 行 |
| 单次文件片段 | 2 MiB |
| 自动刷新最短间隔 | 5 秒 |
| 自动重试 | 0 次 |

说明：

- 同一服务器可以通过不同配置或 SSH 别名重复连接，客户端无法可靠识别它们是同一目标，因此服务器端仍需资源限制。
- 达到预算时返回明确的超时或截断状态，不能把不完整结果伪装成完整结果。
- 取消应终止本地 SSH 子进程并回收资源，但不能声称一定终止已脱离会话的远端进程。
- 第一版不支持无限跟随；日志刷新使用有最短间隔的重复有界查询。

## 错误处理与失败策略

以下情况全部失败关闭：

- 无法读取最新 SSH 配置。
- 配置处于生产模式但调用了完整终端接口。
- 远端平台无法识别或不在支持范围。
- 操作未建模、分类未知或当前平台未实现。
- 参数不合法、路径类型不支持或预算溢出。
- 安全网关版本不兼容。
- 无法确认固定命令模板可以安全构造。

错误信息必须包含操作类型和失败阶段，但不能包含密码、密钥、完整敏感内容或不受限远端输出。

安全诊断失败后：

- 不自动切换到完整 Shell。
- 不自动扩大超时、输出或扫描范围。
- 不自动重试。
- 可以允许用户在相同边界内修改参数后手动重试。

## UI 与交互

### 工作区标识

- 标签和正文持续显示“生产 · 低影响只读诊断”。
- 使用危险色强调目标环境，但不要把正常只读操作渲染为错误。
- 显示连接名、主机、用户和当前保护说明。

### 操作输入

- 以操作选择器和专用表单替代自由命令输入框。
- 参数在本地即时校验。
- 粘贴只填充当前字段，不自动执行。
- 执行按钮显示具体动作，例如“读取日志”，不使用含义模糊的“运行”。

### 结果展示

- 显示开始时间、耗时、退出状态和截断标记。
- 支持本地搜索、过滤、复制和保存结果。
- 保存结果只写本地文件，不改变远端。
- 超时、取消、权限不足和平台不支持使用不同错误提示。

### 拒绝反馈

拒绝信息应说明原因和可行替代，例如：

- “生产模式禁止重启服务；可以使用‘服务状态’查看当前状态。”
- “目录范围过大；请选择具体日志文件或缩小时间范围。”
- “该操作需要完整 Shell；请按正式变更流程处理。”

不展示可以立即绕过限制的按钮。

## 审计与隐私

第一版复用应用日志记录诊断事件，不新增合规级审计系统。

建议记录：

- 时间、`profile_id` 和操作类型。
- 允许、拒绝、成功、失败、超时或取消。
- 耗时、退出码、输出字节数和是否截断。
- 稳定的拒绝原因代码。

默认不记录：

- 密码、密钥、Token 和 AskPass 内容。
- 文件内容、日志内容和完整命令输出。
- 可能包含凭据的完整环境变量。
- 未经脱敏的任意路径和服务参数。

日志消息遵循项目约定使用简洁英文，UI 错误使用中文。应用日志只能用于本地排障；需要不可抵赖或集中审计时，应由服务器、堡垒机或专用审计系统承担。

## 服务器端增强

客户端安全诊断能够保证 Ramag 不提供自由修改入口，但用户仍可能使用其他客户端。因此，高安全环境应增加服务器端保护。

### 推荐措施

- 使用独立只读操作系统账号和独立凭据。
- 不授予 `sudo`，不加入 Docker 等等价高权限组。
- 通过文件权限、ACL 或只读挂载限制写入。
- 限制网络出口、进程数量、CPU、内存和 IO。
- 禁止 Agent、X11、TCP、Socket 和隧道转发。
- 安全终端专用凭据使用 `ForceCommand` 启动固定网关，并禁止 PTY。
- 网关程序由 root 所有且普通用户不可写，内部只接受版本化结构化协议。
- 网关不能执行 `sh -c "$SSH_ORIGINAL_COMMAND"` 或同类原始命令转发。

OpenSSH 的 `ForceCommand`、`DisableForwarding`、`PermitTTY` 和 `ChrootDirectory` 可用于构建受限连接，具体语义见 [OpenSSH sshd_config](https://man.openbsd.org/sshd_config)。Bash 受限模式本身不是完整安全边界，见 [GNU Bash Restricted Shell](https://www.gnu.org/software/bash/manual/html_node/The-Restricted-Shell.html)。

### 与 SFTP 的关系

同一个账号或密钥使用 `ForceCommand` 后可能无法继续使用现有 SFTP 子系统。可选方案为：

1. 安全终端使用独立账号或独立密钥，SFTP 使用现有只读账号。
2. 服务端网关同时提供结构化只读文件能力，替代 SFTP。
3. 只使用操作系统只读权限，不强制网关；此时客户端之外仍可能获得 Shell。

第一版客户端方案不强制部署服务端网关，后续根据部署成本和安全等级选择。

## 平台范围

建议第一版只支持 Linux 远端：

- 本地 Ramag 仍支持 macOS 和 Windows。
- 远端平台在连接或首次诊断时通过被动操作识别。
- 非 Linux 远端显示“生产安全诊断暂不支持该平台”，不得回退完整终端。
- 后续支持 macOS、BSD 或 Windows Server 时，分别定义操作实现和测试矩阵，不能复用未经验证的 Linux 命令。

## 测试与验收

分层测试、回归场景、验收标准和仓库门禁见[生产诊断实现与验证计划](ssh-sftp-implementation-plan.md)。核心安全断言是：所有拒绝决定必须发生在创建远端执行任务之前。

## 优点与代价

### 优点

- 显著降低连接错主机、粘贴错命令和紧急排障误操作的风险。
- 默认拒绝比危险命令黑名单更可验证、更不易产生错误安全感。
- 与数据库和 SFTP 的生产只读语义一致。
- 操作、参数、资源边界和结果可以稳定测试和审计。
- 本地过滤和有界读取减少对生产系统的额外负载。

### 代价

- 生产连接失去完整 Shell 的灵活性。
- 新诊断能力需要逐项建模、实现和测试，扩展成本高于新增命令字符串。
- 第一版无法覆盖所有临时、未知的故障排查手段。
- Linux 发行版、服务管理器和工具版本带来兼容成本。
- 开启生产模式需要关闭已有终端，可能中断正在进行的排查。
- 服务器级不可绕过保护需要额外账号、密钥、网关或隔离部署。

这些代价是明确安全边界的结果。不能为了恢复便利而在生产安全终端中重新加入任意 Shell 输入。

## 落地计划

P0 至 P3 的实施顺序、每阶段范围和验证点见[生产诊断实现与验证计划](ssh-sftp-implementation-plan.md)。在安全诊断能力尚未完成时，应先通过 P0 禁止生产完整终端，不能用危险命令黑名单作为临时替代。

## 待确认事项

以下事项不影响核心方向，但会影响第一版范围：

1. 第一版允许操作的最终清单和展示顺序。
2. 资源预算是否采用本文建议值，或需要按目标机器规格分档。
3. 文件和日志读取是否需要额外的敏感路径限制。
4. 是否接受第一版仅支持 Linux 远端。
5. 关闭生产模式的确认强度和审计保留时间。
6. 是否有部署服务端独立账号或安全网关的条件。

在这些事项确定前，可以先实现 P0；P1 应在操作清单和资源预算确认后开始。
