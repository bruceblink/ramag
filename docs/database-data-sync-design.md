# Ramag 数据库数据同步详细设计

## 文档状态

- 状态：功能实现与自动化验收已完成；发布前人工 UI 与长时间稳定性验收待执行
- 核对日期：2026-08-04
- 用户可见名称：同步
- 代码命名：`data_sync`
- 支持引擎：MySQL、PostgreSQL、MongoDB、Redis
- 同步方向：从源连接单向补齐到当前目标连接
- 核心策略：只创建缺失对象、只写入不存在的数据，不更新、不覆盖、不删除已有数据
- 交互约束：同步开始后展示全窗口占屏进度，并阻止用户执行其他操作
- 质量约束：功能测试、边界测试和真实数据库集成测试属于上线门禁，不是可延后事项

本文记录数据库数据同步的产品语义、引擎边界、名称映射、目标创建、幂等规则、性能方案、占屏交互、安全要求、测试矩阵和验收标准。

数据库同步会直接改变远端数据，而且通常持续时间较长。错误的判重、名称映射、并发处理、TTL 恢复或取消逻辑都可能产生重复、遗漏、半成品或业务数据污染。因此，本功能必须按高风险数据操作设计：实现前先固定语义，实现中保持资源有界，交付前通过完整测试，不允许以“正常路径可以运行”代替正确性证明。

## 结论先行

同步采用“同引擎、手动触发、单向补齐、可重复执行”的模型：

```text
数据源管理中的目标连接
    │
    └── 点击「同步」
          ├── 选择同引擎源连接
          ├── 选择库 / Schema / Collection / DB / 表 / Key 范围
          ├── 配置源名称 → 目标名称映射
          ├── 执行只读预检
          ├── 已有目标对象时二次确认
          └── 获取应用级独占锁
                └── 全窗口占屏显示进度
                      ├── 只允许查看进度
                      └── 只允许请求取消
```

确定的关键决策如下：

1. 只支持同引擎同步，不支持任何跨引擎同步。
2. 当前连接行固定为目标端，用户从其他已保存的同引擎连接中选择源端。
3. MySQL、PostgreSQL、MongoDB 允许创建新的目标库、Schema、表或 Collection，并允许目标名称不同于源名称。
4. Redis 允许选择不同目标 DB，并支持完整 Key 名称映射或前缀映射；Redis 逻辑 DB 不需要创建。
5. 目标对象存在时必须先完成兼容性预检，再进行二次确认。
6. SQL 以主键或全部列非空的唯一键判定记录是否存在；MongoDB 以 `_id` 判定；Redis 以完整 Key 判定。
7. 已有相同身份的数据一律保持不变，即使其他字段或值与源端不同，也不执行更新。
8. 没有可靠唯一身份的 SQL 表不能进入可重复同步，禁止用整行比较或哈希静默兜底。
9. 同步直接在源端和目标端之间分批传输，不通过临时导出文件中转。
10. 同一时刻全应用只允许一个同步任务。运行、取消和收尾期间保持占屏并阻止其他用户操作。
11. 取消或失败时已经提交的数据保留；再次执行同一计划继续补齐，不自动删除用户可见对象。
12. 未完成自动化测试、真实数据库集成测试、故障测试和 UI 占屏门禁测试时，不得交付该引擎的同步入口。

## 目标与非目标

### 功能目标

1. 从另一个已保存连接向当前连接迁移数据。
2. 支持整库和对象级范围。
3. 支持目标库和目标对象使用新名称。
4. 目标对象不存在时创建结构并迁移全部数据。
5. 目标对象存在且兼容时只补齐缺失数据。
6. 支持中途取消、明确进度、结果汇总和安全重跑。
7. 大数据量下保持内存有界，避免逐行或逐 Key 网络往返。
8. 同步期间阻止用户进行其他操作，避免上下文切换、重复提交和连接配置变化。

### 不包含

- MySQL 与 PostgreSQL 之间的转换。
- SQL、MongoDB、Redis 之间的任何转换。
- 双向同步。
- 自动定时同步。
- 实时 CDC、binlog、WAL 或 Change Stream 消费。
- 更新目标端已有记录。
- 删除目标端额外记录。
- 冲突字段合并。
- 视图、触发器、存储过程、事件、账号和权限迁移。
- Redis Stream consumer group、pending entries 和消费位置迁移。
- Redis 模块自定义类型迁移。

这些能力不能通过隐藏开关或未完成入口提前暴露。以后若改变范围，必须先更新本文并补齐相应测试。

## 支持矩阵

| 引擎 | 整体范围 | 对象范围 | 目标名称映射 | 缺失判定 |
|---|---|---|---|---|
| MySQL | Database | Table，可多选 | Database、Table | 主键或非空唯一键 |
| PostgreSQL | Schema | Table，可多选 | Schema、Table | 主键或非空唯一键 |
| MongoDB | Database | Collection，可多选 | Database、Collection | `_id` |
| Redis | DB | 前缀、Key，可多选 | DB、前缀、Key | 目标 Key 是否存在 |

PostgreSQL 连接配置已经固定实际 Database。首版“库级同步”准确指该 Database 内的 Schema；创建新的 PostgreSQL Database 属于独立能力，不在本文范围内。

## 产品语义

### 源端与目标端

- 用户点击某连接行的“同步”，该连接成为固定目标端。
- 源连接必须由用户显式选择。
- 源连接与目标连接必须是同一种 `DriverKind`。
- 源连接不能与目标连接使用同一 `ConnectionId`。
- 若两个不同连接配置明显指向同一实例和同一库，预检必须阻止无意义的同范围同步或给出明确冲突说明。
- 目标连接开启生产只读模式时禁止同步；源连接开启生产只读模式时允许读取。

### “只同步不存在的数据”

SQL：

1. 首选主键作为记录身份。
2. 没有主键时，选择所有列均为 `NOT NULL` 的唯一索引。
3. 没有可靠身份时，该表预检失败。
4. 目标存在相同身份时，整行跳过；不比较、更新其他字段。

MongoDB：

- 使用 `_id` 作为文档身份。
- 目标存在相同 `_id` 时跳过完整文档。

Redis：

- 完整 Key 是最小同步单元。
- 目标 Key 存在时跳过整个 Key，包括其值、内部元素和 TTL。
- 不对 List、String、Hash、Set、ZSet、Stream 做条目级合并。

上述规则保证同步结果幂等。对相同源快照和相同目标状态重复执行，第二次不应产生新的写入副作用。

### 已有数据不变式

同步必须满足以下不变式：

1. 源端不执行任何写操作。
2. 目标端同步前已有的数据不被更新。
3. 目标端同步前已有的数据不被删除。
4. 目标端与同步范围无关的数据不受影响。
5. 同一计划重复执行不会制造重复数据。
6. 取消或失败后再次执行能够继续补齐。

测试必须直接验证这些不变式，不能只验证新增数量。

## 列表入口与配置流程

连接行操作顺序为：

```text
同步 → 修改 → 删除
```

同步按钮使用同步图标，提示文案为“从其他连接同步数据到此连接”。Redis、MongoDB 和 SQL 均使用同一个列表入口，再根据目标引擎展示对应范围。

### 第一步：配置来源与映射

公共字段：

- 目标连接：当前连接，只读展示。
- 源连接：仅显示其他同引擎连接。
- 源范围。
- 目标范围。
- 对象名称映射。

SQL：

- 整库 / Schema：选择源范围并输入目标 Database / Schema 名。
- 表级：选择一个或多个源表，为每个源表输入目标表名。

MongoDB：

- 整库：选择源 Database 并输入目标 Database 名。
- Collection 级：选择一个或多个 Collection，为每个对象输入目标名称。

Redis：

- 整 DB：选择源 DB 和目标 DB；Key 默认保持原名，可选统一增加目标前缀。
- 前缀：配置字面源前缀和字面目标前缀，保留后续 Key 后缀。
- 指定 Key：逐项配置源 Key 和目标 Key。

不支持正则名称替换。映射必须是确定且可证明一一对应的，避免多个源对象落到同一个目标对象。

### 第二步：只读预检

预检不得写数据库，至少检查：

- 两端配置仍存在且未被编辑。
- 两端连通性和服务端版本。
- 目标不是生产只读连接。
- 源、目标范围和名称合法。
- 目标是否为系统库、系统 Schema 或受保护 Redis DB 范围。
- 目标库和对象是否存在。
- 已有 SQL 表的列、类型、生成列、默认值和唯一身份是否兼容。
- 新 SQL 表需要创建的类型、序列、主键、唯一约束、索引和外键。
- MongoDB Collection 的创建选项和索引兼容性。
- Redis 目标 DB 是否可访问，目标 Key 或前缀是否已有数据。
- 映射是否重名、越界或形成无法解析的外键引用。
- 数据类型是否属于正式支持范围。

预检不能默认对大型 SQL 表执行精确 `COUNT(*)`。Redis 整 DB 可使用 `DBSIZE`，因为它是服务端直接维护的计数。

预检结果必须生成不可变的执行计划和目标结构指纹。真正执行前再次核对目标状态；状态变化时中止并要求重新预检，不能使用过期确认继续写入。

### 第三步：确认

全部目标对象都不存在时，计划页给出一次正常确认，明确将创建哪些对象。

只要有目标库、目标对象或目标 Key 已存在，就必须二次确认。确认内容至少包括：

- 已有目标对象。
- 将新建的目标对象。
- 已有数据将保持不变。
- 缺失数据将被补齐。
- 不执行更新、覆盖、删除或清空。
- 取消或失败时已完成部分保留。

二次确认按钮使用“继续同步”，不能使用含糊的“确定”。

Redis 的二次确认条件：

- 整 DB：目标 `DBSIZE > 0`。
- 前缀：目标前缀下至少存在一个 Key。
- 指定 Key：至少一个映射后的目标 Key 已存在。

## 占屏进度与应用级独占锁

### 强制交互原则

同步属于耗时且高风险的数据操作。同步开始后必须展示全窗口占屏进度，并阻止用户进行其他操作。不能只在工具栏显示一行进度，也不能允许用户切换到其他工具继续操作。

占屏开始时间：用户完成最终确认，执行器准备发出第一条写请求之前。

占屏结束时间：执行器成功、失败或取消后，所有在途请求结束、临时资源清理完成，并且用户确认关闭结果页之后。

### 双层门禁

只使用视觉遮罩不够。必须同时实现：

1. 视觉门禁：在窗口根层渲染覆盖整个 Ramag 窗口的同步视图，拦截鼠标和键盘事件。
2. 逻辑门禁：应用级 `DataSyncGate` 标记独占任务，所有用户 Action、菜单、快捷键和连接管理入口在执行前检查该门禁。

运行期间禁止：

- 切换工具。
- 切换或关闭数据库会话。
- 新建、修改、删除连接。
- 执行 SQL、MongoDB 命令或 Redis 命令。
- 导入、导出或启动第二个同步。
- 通过快捷键绕过占屏视图。
- 通过菜单或托盘入口触发其他用户操作。

后台既有服务可以继续完成必要维护，但不能向用户开放新的交互流程。

### 占屏进度内容

占屏视图至少显示：

- 标题：正在同步数据。
- 源连接、源范围。
- 目标连接、目标范围。
- 当前阶段。
- 当前对象及名称映射。
- 对象进度：已完成 / 总数。
- 已扫描条目。
- 已新增条目。
- 已跳过已有条目。
- 失败和警告数量。
- 已传输字节数。
- 已用时间。
- 取消按钮。

总行数未知时不能展示虚假的百分比。可以展示对象级确定进度和条目级活动指示。

### 状态机

```text
Idle
  → Configuring
  → Preflighting
  → AwaitingConfirmation
  → Running（获取应用级独占锁并占屏）
      ├── Cancelling（继续占屏）
      ├── Completed（结果占屏，等待用户关闭）
      └── Failed（结果占屏，等待用户关闭）
  → Idle（释放独占锁）
```

任意异步回包必须携带任务代次 Token。旧任务或迟到回包不能覆盖当前进度，也不能提前释放独占锁。

### 取消

取消不是立即关闭占屏：

1. 用户点击取消。
2. 弹出确认，明确“已完成部分将保留”。
3. 用户确认后进入 `Cancelling`。
4. 取消按钮禁用，文案变为“正在安全停止”。
5. 等待当前批次结束或可取消查询返回。
6. 清理 Redis 临时 Key 等任务私有资源。
7. 展示取消结果汇总。
8. 用户关闭结果页后才释放应用级独占锁。

`Escape` 不得关闭运行中的占屏视图。

窗口关闭时必须提示同步仍在进行。若用户坚持退出，应先请求取消并说明已提交部分会保留；不能假装完成或执行破坏性回滚。

## SQL 同步设计

### 记录身份

身份选择顺序：

1. 主键。
2. 全部列均为 `NOT NULL` 的唯一索引。
3. 无可靠身份：预检失败。

目标已有相同身份但其他列不同，仍然跳过，不更新目标。

### 新对象创建

- MySQL 可创建新的目标 Database。
- PostgreSQL 可在当前连接的 Database 内创建新的目标 Schema。
- 新表使用目标名称生成 DDL，不允许对完整 SQL 做全局字符串替换。
- 创建列、生成列、默认值、主键和唯一约束。
- 数据完成后再创建普通索引和外键，降低写入成本并处理循环依赖。
- PostgreSQL 枚举类型和序列使用目标 Schema / 表名生成。
- PostgreSQL 数据完成后依据目标表最大值安全推进序列，不允许倒退目标序列。

整范围迁移可以通过完整映射解析内部外键。单表迁移遇到目标端不存在的外键引用对象时默认阻止执行，提示用户同时选择依赖表或先准备目标结构。

### 数据路径

新表或确认空表：

```text
源表按身份键 Keyset 分页读取完整行
    → 目标端批量插入
```

已有非空表：

```text
源端分页读取身份键
    → 目标端批量查询已有身份键
    → 回源读取缺失身份对应的完整行
    → 目标端批量插入
```

最终写入仍使用原生冲突保护处理并发竞态：

- PostgreSQL：`ON CONFLICT DO NOTHING`。
- MySQL：`ON DUPLICATE KEY UPDATE <identity>=<identity>`，不使用会吞掉其他数据问题的 `INSERT IGNORE`。

非唯一约束错误、类型错误、长度错误和权限错误必须显式失败。

## MongoDB 同步设计

- 使用 `_id` Keyset 分页扫描。
- 已有 Collection 先批量查询 `_id`，只读取和写入缺失文档。
- 新 Collection 恢复创建选项和索引。
- 普通索引在数据完成后创建。
- 批量写使用无序 `insert_many`，只把重复 `_id` 视为跳过；其他写错误必须失败。
- 目标存在相同 `_id` 但内容不同时保持目标不变。
- MongoDB 视图不在完整 Collection 同步范围内。

## Redis 同步设计

### 同步单位和映射

Redis 以完整 Key 为原子业务单位：

- 整 DB：源 DB 可映射到不同目标 DB，Key 名默认不变，可统一增加前缀。
- 前缀：源字面前缀映射为目标字面前缀，后缀保持不变。
- 指定 Key：逐项配置目标 Key 名。

映射函数必须可证明一一对应。超过 Key 长度限制、含当前界面无法安全处理的字符或映射冲突时预检失败。

### 支持类型

- String / Bytes：`GETRANGE` 分页读取，`APPEND` 写入。
- List：`LRANGE` 分页，`RPUSH` 写入。
- Hash：`HSCAN` 分页，`HSET` 写入。
- Set：`SSCAN` 分页，`SADD` 写入。
- ZSet：分页读取成员与分值，`ZADD` 写入。
- Stream：`XRANGE` 分页，使用原消息 ID `XADD`。

Redis 模块类型、Stream 消费组和二进制 Key 不属于首版。遇到不支持内容必须明确失败或在预检中阻止，不能静默得到不完整目标。

### 缺失检查和原子发布

```text
源端 SCAN Key
    → 计算目标 Key
    → 目标端流水线 EXISTS
    → 已存在：跳过，不读取源值
    → 不存在：分页读取源值并写入随机临时 Key
    → 恢复 TTL
    → RENAMENX 原子发布为目标 Key
```

临时 Key 必须具备任务唯一前缀和自动清理 TTL。取消、失败或目标并发创建时主动删除任务自己的临时 Key；程序异常退出后由临时 TTL 兜底清理。

`RENAMENX` 保证发布时仍不覆盖目标。失败表示目标 Key 已并发出现，应删除临时 Key 并计入“已存在跳过”。

### TTL

1. 首页读取同时获取类型与 PTTL。
2. 完成复制后再次读取源类型与 PTTL。
3. 源 Key 已过期：清理临时 Key，不发布。
4. 类型变化：清理临时 Key，该 Key 失败并等待重跑。
5. 永久 Key：临时 Key 执行 `PERSIST`。
6. 有 TTL：扣除最终检查到发布之间的本地耗时，再执行 `PEXPIRE`。
7. TTL 随 `RENAMENX` 保留到最终 Key。

目标已有 Key 被跳过时，其 TTL 必须保持不变。

## 性能和资源边界

### 通用要求

- 直接连接间传输，不通过临时导出文件中转。
- 复用 `TRANSFER_BATCH_ITEMS = 5_000` 和 `TRANSFER_BATCH_BYTES = 32 MiB`。
- 数据规模增长时内存复杂度保持为 `O(batch)`，不得累积整个库、表、Collection 或 Key 空间。
- 进度更新节流，不能逐行触发 GPUI 重绘。
- 同一时刻只处理一个数据库对象；对象内部可以使用有界流水线。
- 有界通道容量最多为一个待写批次，防止读端远快于写端时放大内存。
- 不允许逐行、逐文档或逐 Key 发起独立存在性网络往返。
- 不进行应用层写操作盲目重试。只有明确未产生副作用的幂等读取可以有界重试。

### SQL 和 MongoDB

- 使用身份键 Keyset 分页，不使用大偏移 `OFFSET`。
- 已有目标对象先批量查询身份键，再拉取缺失完整数据。
- 新对象和空对象直接读取完整批次，避免额外存在性查询。
- 大字段和单文档必须受单条与批次字节边界保护。

### Redis

- 源端 `SCAN COUNT 5000`。
- 目标端通过 Pipeline 批量检查 `EXISTS`。
- 只有缺失 Key 才读取完整值。
- 大 Key 分页复制，一次只复制一个大 Key。
- 首页预取数量和累计字节必须同时受限；不能只限制 Key 数量。
- SCAN 可能重复返回 Key，目标存在性检查自然去重，不保存无界已见集合。

没有业务更新时间或 CDC 时，重复同步仍需扫描全部身份键或 Redis Key。本文承诺幂等补齐，不承诺真实增量复杂度为 `O(delta)`。

## 一致性、并发和恢复

- 默认是在线尽力一致，不是全库一致性快照。
- 源端持续写入时，单次同步可能看见不同时间点的数据；再次执行应补齐遗漏的新身份。
- 需要严格快照时，用户应先暂停源端写入。以后若增加快照模式，必须评估长事务、MVCC 膨胀和锁影响。
- 目标并发插入由数据库原生冲突保护或 Redis `RENAMENX` 兜底。
- 每批独立提交，避免大事务长期持锁和放大 WAL / binlog。
- 取消或失败后已提交批次保留。
- 不自动删除已创建的用户目标库、表或 Collection，避免错误回滚用户数据。
- Redis 仅自动清理任务私有临时 Key。
- 重新执行相同计划是标准恢复方式。

### Domain 与纯逻辑测试

- 同引擎连接过滤，跨引擎请求被拒绝。
- SQL 主键、复合主键和非空唯一键选择。
- 可空唯一键不得作为可靠身份。
- 无身份表预检失败。
- Database / Schema / Table / Collection / Redis Key 名称边界。
- Unicode、引号、反引号、保留字和控制字符。
- 多源对象映射到同一目标对象被拒绝。
- SQL DDL 名称映射不能修改字符串字面量、注释和无关标识符。
- Redis 前缀映射保持后缀且具备单射性质。
- 进度和汇总饱和计数，不发生整数溢出。
- 目标结构指纹稳定，任一关键字段变化都能失效计划。

### App 层测试

使用 Fake Driver 构造可控数据集和故障点：

- 空源、空目标。
- 新目标对象创建后完整复制。
- 已有对象只补齐缺失身份。
- 相同身份但不同内容时目标保持不变。
- 目标端额外数据保持不变。
- 相同计划连续执行三次，第二、三次新增均为零。
- 目标在预检后发生结构变化，执行前被阻止。
- 目标在批次写入前并发插入，冲突被安全跳过。
- 每个批次前、读取中、写入中、提交后注入失败。
- 取消前、取消中和任务完成竞态。
- 迟到异步回包不能覆盖新任务状态或释放门禁。
- 错误、取消和成功路径都能得到准确汇总。

### SQL 边界测试

- 0、1、4,999、5,000、5,001 行。
- 单列和复合主键。
- 目标键存在缺口，例如已有 1、3，能够补入 2。
- 主键冲突、其他唯一键冲突和普通数据错误正确区分。
- 生成列不参与写入。
- 自增列和 PostgreSQL Identity 显式值迁移。
- PostgreSQL 序列不倒退。
- 外键依赖、循环外键和缺失依赖。
- 普通索引延后创建。
- 字符集、排序规则、枚举、JSON、Decimal、日期时间、二进制和大文本。
- 32 MiB 前一字节、恰好 32 MiB、超过一字节。
- 目标表列缺失、类型不兼容、额外非空无默认列。
- 名称达到数据库限制和超过限制。
- 源端并发新增、修改、删除时不崩溃并给出一致性警告。

### MongoDB 边界测试

- 空 Collection、单文档和跨 5,000 文档批次。
- 混合类型 `_id` Keyset。
- 目标 `_id` 缺口补齐。
- 同 `_id` 不同内容不更新。
- 重复键与其他批量写错误区分。
- Collection 选项、Validator、Collation、Time Series 和索引恢复。
- 单文档接近、等于和超过 32 MiB 应用传输边界。
- 源文档并发删除或修改。
- MongoDB 视图明确拒绝。

### Redis 边界测试

- DB 0 到不同目标 DB。
- 整 DB、前缀和指定 Key 三种范围。
- Key 保持原名、增加前缀、替换前缀和单 Key 改名。
- String、Bytes、List、Hash、Set、ZSet、Stream。
- 空 String、重复 List 元素、二进制 Value、ZSet 浮点分值和 Stream 原 ID。
- 大 String、多页 List / Hash / Set / ZSet / Stream。
- 目标 Key 已存在时值、类型和 TTL 完全不变。
- 目标 Key 在 `EXISTS` 后、发布前并发创建，`RENAMENX` 不覆盖。
- 源 Key 在读取中消失、过期或改变类型。
- 永久 TTL、短 TTL、毫秒 TTL和复制中途过期。
- TTL 不因同步耗时而延长。
- SCAN 重复 Key。
- Redis 模块类型和二进制 Key 明确拒绝。
- 取消、失败和进程异常后的临时 Key 清理。
- 临时 Key 不得泄露到最终命名空间或长期残留。

## 已确认的不可变决策

1. 数据同步是高风险、强正确性功能，测试和边界验证优先级与实现相同。
2. 同步是耗时操作，运行期间必须占屏并阻止用户执行其他操作。
3. 只支持同引擎同步，不考虑跨引擎。
4. 只补齐不存在的数据，不更新、不覆盖、不删除已有数据。
5. 允许创建新目标库和对象，并允许目标名称不同于源名称。
6. 目标已有对象时必须二次确认。
7. 所有既定范围必须完整实现和验证后才算交付。
