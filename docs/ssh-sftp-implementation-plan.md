# SSH + SFTP 生产诊断实现与验证计划

## 文档状态

- 状态：设计方案，尚未实现
- 上位设计：[SSH + SFTP 生产低影响只读诊断模式设计](ssh-sftp-design.md)
- 适用范围：领域接口、应用门禁、OpenSSH 适配、UI、测试和分阶段交付

本文只描述如何实施和验证生产诊断模式。产品行为、安全承诺、允许与禁止操作、资源预算及服务器边界以上位设计为准；两份文档冲突时，应先修订并统一设计，不能自行选择较宽松的解释。

## 实现原则

1. 生产连接不创建完整交互 Shell。
2. 诊断请求使用封闭的结构化类型，不接受任意命令字符串。
3. 拒绝决定发生在创建 SSH 子进程或远端请求之前。
4. UI、应用层和基础设施层均有门禁，应用层是业务规则中心。
5. 配置读取、策略判断、平台识别或参数校验失败时关闭执行路径。
6. 不自动回退完整终端，不自动重试，不自动扩大资源预算。

## 领域模型建议

生产诊断请求必须使用封闭枚举表达，不暴露 `program`、`args` 或原始命令字符串：

```rust
pub enum SshDiagnosticOperation {
    SystemOverview,
    ResourceSnapshot,
    ProcessList,
    NetworkSnapshot,
    DiskOverview,
    FileMetadata { path: String },
    FileChunk {
        path: String,
        position: RemoteFileChunkPosition,
    },
    LogQuery {
        source: SshLogSource,
        max_lines: u16,
    },
    ServiceStatus { name: String },
}
```

示例只表达接口方向，最终类型应按现有实体复用情况拆分。建议新增 `crates/ramag-domain/src/entities/ssh_terminal.rs`，避免继续扩大 `ssh.rs`。

结果至少包含：

- 标准输出和标准错误的有界内容。
- 退出码或终止原因。
- 是否因为大小限制截断。
- 实际耗时。
- 平台或操作不支持时的明确错误。

领域模型不得依赖 GPUI、PTY 或具体 OpenSSH 实现。

## 接口方向

### 完整终端

现有 `SshService::terminal_command` 应改为根据 `profile_id` 获取最新配置。生产配置直接返回 `DomainError::Forbidden`，非生产配置继续返回 `SshLaunchCommand`。

基础设施的终端命令构造再检查一次 `profile.production`，防止未来新增调用路径绕过应用层。

### 安全诊断

`SshDriver` 增加表达结构化诊断的接口，应用层负责策略与参数校验，基础设施层负责固定执行实现。接口不能接收原始命令，例如：

```rust
async fn execute_diagnostic(
    &self,
    profile: &SshProfile,
    operation: &SshDiagnosticOperation,
    cancellation: DiagnosticCancellation,
) -> Result<SshDiagnosticResult>;
```

最终是否流式返回，应根据 UI 实际需求决定。第一版输出上限为 2 MiB，可以先返回有界结果，避免为了预想中的持续日志引入复杂流协议。

## 分层职责

### `ramag-domain`

- 定义诊断操作、参数值对象、结果和 `SshDriver` 抽象。
- 定义长度、行数和输出预算等跨层常量。
- 不解析 Shell，不依赖终端或 UI。

### `ramag-app`

- 根据 `profile_id` 加载最新配置。
- 生产配置拒绝 `terminal_command`。
- 编排诊断操作、参数校验、取消和结果边界。
- 在调用驱动前完成默认拒绝策略。
- 建议把新增逻辑放入 `ssh_service/terminal.rs`，避免继续增大主用例文件。

### `ramag-infra-ssh`

- 对生产配置启动完整终端再次防御性拒绝。
- 把结构化操作映射为固定执行实现。
- 禁止把用户输入拼接为任意 Shell 命令。
- 安全诊断默认使用 `ssh -T`，不分配交互 PTY，不提供用户 stdin。
- 对 stdout、stderr、进程时间和退出状态实施硬限制。
- 建议将诊断构造与执行拆入独立模块，保持 `command.rs` 聚焦。

### `ramag-tool-ssh`

- 生产工作区渲染安全诊断终端。
- 提供结构化输入、参数提示、结果展示、取消和本地过滤。
- 处理生产模式切换时的终端冻结、确认和关闭。
- 不在 UI 中复制应用层安全规则；UI 门禁只用于及时反馈。

### `ramag-terminal`

- 保持通用 PTY、ANSI 和原始终端职责。
- 不依赖 SSH 领域模型，不维护危险命令清单。
- 如需复用终端渲染，可以增加“仅显示输出、禁止用户输入”能力，但安全诊断不通过 `TerminalCore::send` 执行命令。

## 参数与输入校验

### 通用规则

- 拒绝 NUL、换行和控制字符。
- 遵守现有 SSH 路径与文本长度上限。
- 数字参数使用类型和闭区间校验，不接受自由文本数字表达式。
- 服务名使用明确字符集和长度限制。
- 路径在执行前规范化；拒绝设备、Socket、FIFO 和其他不支持类型。
- 文件读取使用只读打开方式，并限制单次读取窗口。
- 不允许用户覆盖 PATH、PAGER、EDITOR、SHELL 等环境变量。
- 不继承可能改变工具行为的非必要远端环境变量。

### Shell 构造规则

理想实现是服务端安全网关直接接收结构化请求，不经过 Shell。没有网关的客户端第一阶段只能执行固定模板，并遵循：

- 程序和选项由代码固定，不能由用户提供。
- 用户参数单独验证并采用正确的平台转义。
- 能使用 `--` 终止选项时必须使用。
- 不支持包含管道、重定向、命令替换或控制运算符的模板。
- 无法安全表达的操作不实现，不能退回 `sh -c` 拼接。

## 状态切换实现

### 开启生产模式

1. UI 将相关 `TerminalView` 输入状态改为冻结。
2. 统计活动终端并显示影响确认。
3. 用户取消时恢复输入，不保存配置。
4. 用户确认时关闭全部 PTY，递增终端 generation，使异步启动结果失效。
5. 终端关闭完成后保存生产配置。
6. 刷新工作区并显示安全诊断终端。

保存和关闭之间必须避免出现旧终端重新加入工作区的竞态。不能只依赖按钮禁用，应用服务启动终端时仍要读取最新配置。

### 关闭生产模式

1. 显示主机、用户和保护降级说明。
2. 要求输入连接名称。
3. 保存非生产配置。
4. 只允许之后新建完整终端，不恢复旧进程。
5. 记录降级事件，不记录凭据或完整远端内容。

## 测试方案

### 领域与纯逻辑测试

- 每种操作分类准确。
- 未知操作默认拒绝。
- 路径、服务名、行数、时间范围和大小边界。
- NUL、换行、控制字符、超长 UTF-8 和边界数值。
- 资源预算的溢出和截断计算。

### 应用层测试

- 生产配置调用完整终端时返回 `Forbidden`。
- 被拒绝操作不会调用 `SshDriver`。
- 允许操作使用最新持久化配置，而不是旧工作区副本。
- 配置读取失败、配置删除和生产状态变化全部失败关闭。
- 非生产终端行为保持不变。
- SFTP 读操作允许，所有远端写操作继续拒绝。

### 基础设施测试

- 生产配置不能构造 `ssh -tt`。
- 安全诊断不分配 PTY，不开放用户 stdin。
- 固定操作无法被参数注入为额外选项或 Shell 语法。
- stdout、stderr、超时、取消和子进程回收有界。
- 输出达到限制时明确标记截断。
- 不支持的平台和网关版本返回可定位错误。

### UI 测试

- 生产工作区不创建普通 `TerminalView`。
- 生产标识、操作列表和资源说明可见。
- 参数非法时执行按钮禁用并显示原因。
- 粘贴不会自动执行。
- 不存在单条操作绕过按钮。
- 开启生产模式时冻结并关闭已有终端。
- 用户取消切换时恢复终端输入且配置不变。
- 关闭生产模式需要显式降级确认。

### 集成与回归测试

- 使用测试 SSH 服务器验证允许操作的结果和边界。
- 验证拒绝操作不会抵达远端审计日志。
- 验证超时和取消后无本地 SSH 子进程残留。
- 验证连接断开、主机指纹、AskPass 和错误映射不回归。
- 验证工作区恢复不会恢复历史终端进程。

迭代期间优先使用对应 crate 的聚焦测试。交付前通过仓库封装运行：

```text
make test
make clippy
make fmt-check
```

## 验收标准

实现完成必须同时满足：

1. 生产配置无法通过任何现有 UI 路径启动完整 SSH Shell。
2. 绕过 UI 直接调用应用服务仍会被拒绝。
3. 绕过应用层直接构造基础设施终端仍有防御性拒绝。
4. 安全诊断只接受封闭的结构化操作，不接受任意程序或命令字符串。
5. 未知操作、无效参数和不支持平台在连接远端前被拒绝。
6. 允许操作具有并发、超时、输出和扫描范围上限。
7. 生产切换会处理全部已打开终端，不留下可继续输入的旧视图。
8. SFTP 现有只读保护和非生产完整终端不回归。
9. UI 和文档均明确客户端保护边界，不宣传为服务器绝对只读。
10. `make test`、`make clippy` 和 `make fmt-check` 全部通过。

## 分阶段落地

### P0：建立硬边界

- 修改生产模式语义和 UI 文案。
- 应用层、基础设施层拒绝生产完整终端。
- 开启生产模式时冻结并关闭已有终端。
- 更新现有“生产模式允许 Terminal”的回归测试。
- 尚未实现安全诊断操作时，生产终端区域显示能力说明和暂不可用状态。

P0 完成后，Ramag 已经能够保证生产模式不通过终端发送新命令。

### P1：提供高频安全诊断

- 实现结构化诊断领域模型和应用服务。
- 支持系统概况、资源、进程、端口、磁盘、文件片段、日志和服务状态。
- 增加超时、输出、并发、取消和本地过滤。
- 完成 Linux 远端集成测试。

### P2：服务器端强制保护

- 设计版本化安全网关协议。
- 使用独立账号或凭据、`ForceCommand`、禁止 PTY 和转发。
- 增加服务器资源限制和集中审计。
- 评估网关与现有 SFTP 的凭据和连接关系。

### P3：按场景扩展

- 根据真实排障频率增加新的结构化操作。
- 每项新增操作单独评估数据、状态、主动探测和资源风险。
- 评估其他远端平台支持。
- 只有出现明确合规需求时再建设专用审计存储。

## 实施前检查

开始 P0 前确认：

- 现有生产配置行为变更已被接受。
- UI 可以枚举、冻结和关闭一个配置下的全部终端。
- 完整终端门禁的错误文案已经确定。

开始 P1 前确认：

- 第一版操作清单和资源预算已经确定。
- 第一版仅支持 Linux 远端已经被接受。
- 文件和日志的敏感路径策略已经确定。
- 是否部署服务端网关已经决定；未部署时明确客户端边界。
